# VPS Deals Wire：SEO、推广与盈利开发计划

版本：2026-10-23；执行周期为 2026-10-23 至 2027-01-20（90 天）。时区：北京时间。计划不等于已创建任务或已执行推广。

## 目标与现有证据

目标是获得有明确购买意图的自然搜索用户，帮助他们完成真实比较，再通过已获批的联盟关系产生可核实、可结算的收入。优先顺序：数据可信 → 搜索可见 → 有效访问 → 联盟点击 → 获批订单 → 已结算收入。

当前已知：32 家来源、28 篇文章；已提交的 2026-10-23 快照有 222 条提取记录，部分缺少计费周期。静态站部署和页面验证可用。旧交接的 GSC、UV、审批数及收入没有本环境独立后台证据。**不能把 222 个金额叫作 222 个可买的月付 VPS 套餐，不能把点击叫作收入。**

主主题继续围绕 cheap VPS；旧计划到 10 月 26 日锁定主词，至少在此之前不调整定位。没有数据支撑前，不以追逐大词排名、每日发文数量或“90 天必赚多少钱”作承诺。

## 先修复的基础

本次代码修复涵盖：robots 和跳转检查、金额计费周期证据、联盟披露配置联动、移除硬编码 FX 排名、机器数据币种纠错、文章目录 CollectionPage、文章 updated 对应 sitemap、22 篇过长标题/描述精简、自动化回归测试，以及最小联盟点击/订阅请求事件。独立 Worker 的 pending 双记录 TTL、月付历史隔离与不同快照确认已完成源码和模拟测试，但尚待有权限的发布通道部署；Pages 上线不会使它生效。保留原 slug、文章正文和 6 篇已有合格 P0 元数据。

短标题/描述只是可读性和摘要展示优化，不是 Google 排名保证。没有文章 FAQ 不自动构成技术缺陷，不为富结果批量拼 FAQ 或评分。页面可返回 200 也不等于被收录。

## 推广渠道及边界

1. **站内与自然搜索优先。** 文章内链使用自然锚文本，连接相关问题、比较页和来源。主导航不塞关键词，避免制造大量筛选参数索引页。重点跟踪页面级展示和有效入口。
2. **价格数据资产。** 每月更新一次有真实样本、原始币种、明确周期和抓取日期的简报。附方法、可下载数据和局限，使媒体/读者有理由引用。绝不跨币种直接排序或推广未经验证的最低价。
3. **YouTube / X。** 原自动化任务先核实是否在运行，避免重复发布；每周从 1–2 篇实质内容拆解图表/短视频/文字洞察。引用可打开的站内出处，按渠道规范分发，不批量刷帖。待评估的渠道链接可以在自有链接上用 UTM，不能擅自改联盟追踪 URL。
4. **有针对性的媒体联系。** 先查看上一轮公开投放与回音；按原交接建议 11/01 前后再评估下一批。准备 3–5 个真正相关的目标与不超过三句话的草稿，附能打开的数据资产链接。未经明确指令不代发邮件、表单或论坛帖；不追发同一家、不买目录、不交换链接。
5. **保留订阅定位。** 价格提醒只发送用户已确认订阅的事务性通知，不把现有订阅名单变成营销群发名单。新增内容邮件需要单独产品设计与用户选择，不能悄悄改用途。
6. **广告后置。** 默认新增支出为 0。按旧运营门槛，先验证连续 7 天每日 UV >100，再由用户决定是否进行 AdSense 预检；这是内部决策条件，不是 Google 官方资格承诺。不买流量、不购买链接。

## 盈利闭环与事件口径

初期专注已经核实获批的联盟，不引入购买/结账功能。比较完整总成本、地区限制、续费与退款，不只突出首期低价；CTA 使用“查看官方价格 / 条款”，不写无证据的“最佳”“限时”。

- `affiliate_click`：明确点击了带 sponsored 属性的官网按钮或卡片。参数仅 provider_slug、placement、page_path；不包含邮箱、秘密、追踪参数。GA4 是观测工具，不等于联盟后台的有效点击。
- `alert_request_accepted`：订阅 API 返回成功。不能算确认订阅；确认、投递、退订应由 Worker 状态或安全聚合计数另行验证。
- `confirmed_sale` / `settled_revenue`：以联盟后台对账为准。没有报告就写未知；订单取消、退款和未结算分别记录。不从页面点击推算“已赚到”。
- 收入模型：自然搜索有效会话 × 联盟出口点击率 × 联盟确认订单率 × 单笔平均净佣金。各系数来自同一时间窗口和匹配口径；参数不足时只保留公式，不编收入预测。
- 页面实验：每次只改一个主要变量，例如 CTA 文案或比较表顺序。记录起止日期、版本、合格会话、点击、确认销售及限制；样本少时说明仅为观察结果。

## 每周仪表盘

| 指标 | 来源与分母 | 诊断用途 |
|---|---|---|
| 可索引/已收录目标 URL | sitemap 与 GSC Page indexing；不要求所有 URL 必须收录 | 技术、重复与价值问题，不把提交 sitemap 当收录 |
| 非品牌搜索展示、点击、CTR | GSC，同一 property/国家/设备/搜索类型，最近完整 28 天对前 28 天 | 有展示无点击：检查意图与摘要；无展示：检查索引与主题价值 |
| 自然搜索有效入口 | GA4 organic search 会话；排除自己的测试与已知 bot 影响 | 判断吸引的是潜在买家还是噪声流量 |
| 联盟点击率 | 具备联盟出口的有效会话中发生至少一次 affiliate_click 的会话比例 | 会话去重；避免把所有事件次数直接除以页面浏览 |
| 联盟有效点击/确认订单/净佣金 | 各网络后台，注明归因窗、拒绝/退款/待结算与已结算 | 判断真实商业效果；不同网络不得直接相加重复计单 |
| 价格完整性 | 来源抓取成功率、明确周期率、规格/续费覆盖、过期记录数 | 流量增长前先保证决策信息可靠 |
| 内容投入 | 本周实质改进页数、来源核验、对应入口与成本 | 淘汰只增加数量的工作 |

第一周填写基线表；当前 GSC、GA4、联盟订单和收入均为“待后台核验”，不是 0。第 30 天以方向性变化诊断，第 60/90 天用完整窗口评估；任何数值增长目标要在拿到基线后确定，不保证排名、流量或收益。

## 仍需后台证据的事项

在无关工作完成前不反复索取权限：先完成代码修复、构建和已有公开页面验证。需要继续运营时，用原平台授权或只读导出核对 GSC、GA4、联盟及 cron；不要在聊天发送密码或 token。需要真实邮件测试时由用户指定并授权收件地址。

可参考的官方原则：[有帮助的内容](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)、[链接最佳实践](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)、[sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview)。这些原则不能替代站点本身的实际数据和测试。
